# Email Verifier API

> Real-time email verification delivered as a single REST endpoint. A 16-point engine
> (syntax, DNS, MX, live SMTP handshake, mailbox existence, catch-all, greylisting,
> disposable, role account, spam trap, complainer, gibberish, offensive language,
> B2B/B2C classification, typo correction, SMTP provider identification) returns a
> deliverability verdict for one address per call. Usage is metered against a
> pay-as-you-go credit balance that never expires; only mailbox-level "Paid" outcomes
> consume a credit.

Generated by API Evangelist on 2026-08-13 from this provider's apis.yml and repository
artifacts. The provider publishes its own llms.txt at https://emailverifierapi.com/llms.txt;
it could not be read during this pass because the origin's firewall refused the request

## How to call it

- Base URL: `https://emailverifierapi.com/v2` — one path, `/`, both GET and POST.
- Auth: API key as the `apiKey` **query** parameter on every request. There is no header form.
- Input: `email` (required). `xml=true` switches the response to XML. There is no `Accept`
  header negotiation.
- POST accepts `email` as `application/x-www-form-urlencoded` and is the recommended form for
  server-to-server and agent traffic, because it keeps the address out of URLs and access logs.

## Reading the response

- `status` — `passed` | `failed` | `unknown` | `transient`. **A 200 OK is not a deliverable
  address.** Branch on `status` first.
- `event` — the granular outcome: `mailboxExists`, `mailboxDoesNotExist`, `mailboxIsFull`
  (all billed), `invalidSyntax`, `domainDoesNotExist`, `mxServerDoesNotExist`, `isCatchall`,
  `isGreylisting`, `transientError` (all free).
- `details` — human-readable explanation.
- `emailSuggested` — the corrected address when a domain typo was detected; otherwise null.
- Intelligence flags — `isDisposable`, `isRoleAccount`, `isFreeService`, `possibleSpamtrap`,
  `isComplainer`, `isGibberish`, `isOffensive`.
- `remaining` — credit balance after this call (returned as a **string**).
- `execution` — wall-clock seconds for the verification.
- Errors reuse the same `{status, event, details}` envelope: 401 invalid key, 402 out of
  credits, 429 rate limited, 503 unavailable. No `application/problem+json`, no `Retry-After`.

## Things an agent should know

- No idempotency key and no de-duplication: a blind retry of a Paid event is billed again.
  Cache results client-side keyed on the normalized address.
- No batch, list, pagination, filtering or expansion surface. One address per call.
- No webhooks, no events, no async surface. Verification is strictly synchronous.
- No published rate-limit headers. The credit balance in `remaining` is the only quota signal.
- The credential is in the URL; rotate any key that may have reached a log.
